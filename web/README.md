# web: the Astro version of the three sites

One Astro project builds **brightyard.in**, **allocivo.brightyard.in** and **xessly.brightyard.in** from shared components.
It replaces `build-src/` and the generated files in the repository root once the migration is finished (see `CLAUDE.md`).
Until then the live sites still come from the old files; nothing in this folder is served.

## Commands (run inside `web/`)

Install once (needs Node.js 22.23.4 or newer):

```bash
npm install
```

Build all three sites into `dist/main`, `dist/allocivo` and `dist/xessly`:

```bash
npm run build
```

Build one site: `npm run build:main`, `npm run build:allocivo` or `npm run build:xessly`.

Preview while editing (forms and the API don't work here):

```bash
npm run dev
```

That is brightyard.in at http://localhost:4321. `npm run dev:allocivo` (port 4322) and `npm run dev:xessly` (port 4323) do the same for the product sites.

Compare the new pages with today's live files (needs a build first):

```bash
npm run test:shell
```

## Where things are

| Path | What it is |
|---|---|
| `astro.config.mjs` | Reads `ASTRO_SITE` (`main`, `allocivo` or `xessly`) and builds that site |
| `src/sites/<site>/site.mjs` | Each site's address, name and page list (address, page file, title) |
| `src/sites/<site>/pages/` | Each site's page files. Not in `src/pages/`, which Astro would publish on every site; `src/integrations/sites.mjs` adds only the current site's pages |
| `src/sites/shared/` | `robots.txt` and `sitemap.xml`, written for whichever site is built |
| `src/layouts/` | `Base` (head, styles, fonts), `MainLayout` (brightyard.in shell), `ProductLayout` (product site shell) |
| `src/components/shared/` | Used by all three: icon sprite, page curtain, live demo templates, blueprint data |
| `src/components/main/` | brightyard.in: header with the mega menu (`megamenu/`), footer, preloader, Yard menu dock, assistant, blueprint template, old-address forwarder |
| `src/components/product/` | Product sites: header, footer, closing band |
| `src/lib/links.mjs` | Every internal link. Components write `link('contact')`, never a path |
| `src/lib/page.mjs` | `SCRIPTS_PORTED` switch and the no-JavaScript rules (see below) |
| `src/styles/` | Today's stylesheet in its original parts, in the same order. Shipped unminified, exactly as written |
| `src/assets/fonts/` | Inter and Instrument Serif (SIL OFL) |
| `src/data/master.json` | Blueprint master data |
| `src/lib/blueprint/` | Blueprint engine and brief builder (browser and API share them) |
| `functions/` | Cloudflare Pages Functions (the API), one copy for all three projects. `functions/_lib/{engine,brief,master}.js` are generated by `npm run build` |
| `public/<site>/` | Files copied as they are: favicon, share image |
| `tests/compare-shell.mjs` | Old-against-new check: HTML of the shared parts, `<html>`/`<body>` attributes, head tags, the stylesheet, header, footer and band screenshots (desktop and phone), old `#/` addresses |

## Addresses

- brightyard.in: `/`, `/services`, `/products`, `/how-we-work`, `/work`, `/insights`, `/contact`, `/privacy`, plus a not-found page.
- Product sites keep their folder addresses: `/how-it-works/`, `/integrations/`, `/demo/`, `/agent-flow/`, `/where-fixes-land/`, `/early-access/`.
- Old addresses (`brightyard.in/#/services/svc-eng`, `#/how`, `#/allocivo/al-demo`…) are forwarded by `src/components/main/HashForward.astro`, which uses the same table as `link()`. `#/home/…` and share links (`#/plan/…`) stay on the home page.
- The product sites link to brightyard.in's new addresses (`https://brightyard.in/contact`), so **brightyard.in must switch first, or all three together**.

## Migration status

1. **Done: project structure.** All three sites build. Every page has the real shell (head, header, mega menu, footer, dock, templates) and passes the comparison test. Page bodies are empty, except the product not-found pages.
2. **Next: port the page content** into components, page by page, extending `tests/compare-shell.mjs` to whole pages.
3. **Port the scripts** into `src/scripts/` as per-page modules, then set `SCRIPTS_PORTED = true` in `src/lib/page.mjs`. Until then pages load no JavaScript and use today's no-JavaScript rules, so nothing stays hidden behind an animation that never runs.
4. **Switch Cloudflare** (each of the three projects): root directory `web`, build command `npm run build`, output directory `dist/<site>` (`dist/main`, `dist/allocivo`, `dist/xessly`), variable `ASTRO_SITE` = `main`, `allocivo` or `xessly`. Bindings and secrets stay as they are. Cloudflare uses the same build settings for previews and the live site, so once they change, nothing goes to `main` until the merge.
