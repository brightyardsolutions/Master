|---|---|---|

## How the code is organised

- **Edit `build-src/`, then run `python3 build-src/build.py`.** `index.html`, `assets/css/site.css`, `assets/js/*.js`, `functions/` and `sites/` are generated. See `build-src/README.md` for what comes from where.
- brightyard.in is one HTML page with hash routes (`#/services`, `#/how`…). `SITE.productSites` (in `build-src/build.py`) sends product links and old `#/allocivo…`, `#/xessly…` addresses to the subdomains.
- Product sites are generated by `build-src/src/products.py` from the product sections of `index.html`. They run the same `app.js` in a one-page product mode (`<html data-product="allocivo">`).
- 3D: three.js scenes in `build-src/src/scenes.js` (hero, Allocivo and Xessly stories, Yardie, the blueprint solution model), lazy-loaded as `assets/js/scenes.js`.

### Features worth knowing

- **Brief to blueprint** (home page): a rules engine (`src/engine.js` + `src/master.json`) turns a typed problem into a plan. Yardie, the 3D mascot, presents it as a four-chapter solution model (What we heard, The solution, How we build it, By when). `npm test` checks 66 example briefs; add a case to `tools/engine-cases.mjs` whenever a real brief lands on the wrong plan.
- **Lead flow**: "Email me this blueprint" (email only), then an optional engineer review (name, company, role, timing). There is also a share link (`#/plan/…`) and a printable one-page brief.
- **Mega menu**: glass panels; Products menu with live product cards; Services menu with previews and a Yardie input that routes a one-line brief.
- **Forms**: contact, Allocivo demo and Xessly early access all post to `/api/contact`.

## Backend (Cloudflare Pages Functions, `build-src/src/functions/`)

- Endpoints: `POST /api/blueprint`, `/api/blueprint/review`, `/api/contact`, `/api/event` (daily counts only, no cookies or ids).
- Email: **Zoho ZeptoMail via `https://cpaas.zoho.in/v1.1/email`** (the account is on Zoho CPaaS; `api.zeptomail.in` does not reach it). Sender `hello@brightyard.in` is the only allowed sender.
- Settings in **each** of the three projects, for Production and Preview:
  - `DB`: D1 binding to the `brightyard` database (tables in `schema.sql`; paste it into the D1 console without `--` comments);
  - `ZEPTOMAIL_TOKEN`: a Secret;
  - `MAIL_FROM` = `Brightyard <hello@brightyard.in>`;
  - `TEAM_EMAIL` = `hello@brightyard.in` (the bare address);
  - `SITE_URL`: that project's own address.
- Protection and retention: a honeypot field `website`, same-site checks, hourly per-network limits (8 packs, 5 reviews, 6 contact messages) using a salted hash that changes every hour, and leads deleted after 12 months.
